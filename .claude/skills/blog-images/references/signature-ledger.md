# Signature ledger

The one rule that makes every article's artwork feel bespoke: **each article's cover carries its own
diagram archetype, and no two articles repeat it.**

The genome is constant: dark ground, the palette, Urbanist, one accent subject, flat orthographic
drawing. The *signature* is the **kind of object** the cover is built from, and it must be
structurally distinct from everything already shipped.

Borrowed wholesale from `hyperframes-reel/references/signature-ledger.md`, which is the only
mechanism in this repo that has actually kept a batch visually distinct over a dozen artefacts.

**Before authoring a cover:** read this ledger. Pick an archetype that is a different *kind of
object* from every row below, not a restyle of one. A ladder, a track, a dial, a split panel, a
stack and a branching tree are six different worlds. Two hub-and-spoke graphs are one world.

**After shipping:** append a row. This file is the memory that keeps the batch diverse.

## The test

Cover the labels. If two covers still read as the same drawing, one of them is wrong.

## Worlds already used, do not reach for these again

two facing panels · a side-on stack · a calibrated ladder · a gauge with a dead zone ·
a station pipeline · a rail versus a tree · a balance / lever · a switchboard · a nested
containment · a grid that fills · a timeline with an early break · a map with a boundary

## Worlds still open

a timeline with a break · a funnel (cover-available; used only as a
supporting figure so far) · a ledger/table that reconciles · a container that leaks
(cover-available; used only as a supporting figure so far) · a lens or filter stack

Note: `codex-vs-claude-code` also used a funnel (3 tests converging) and a leaking container
(cost mismatch) as **supporting figures**, not covers. Both stay open for a future cover -
this ledger only tracks the cover archetype.
