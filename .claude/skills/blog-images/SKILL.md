# Blog Images

Turns a finished article into **3 to 4 minimalist explainer diagrams**: one cover and two or three
supporting figures. Every image is authored as SVG against a fixed palette contract and rendered to
PNG. Nothing is generated by an image model.

The sibling of `linkedin-infographics`, and deliberately different in one respect. That skill emits
a paste-ready Gemini prompt for a single dense infographic. This one produces real files, because
these images explain concepts and **the labels are the payload**. Image models garble text inside
diagrams, and `15-brand-visual-identity.md` §3 specifies exact hex values a generative model can
only approximate.

## Why this exists

`15` §6 already specifies this brand's imagery and nothing in the repo produced it:

> "Diagrams over photographs. This brand sells systems, and a system is better drawn than
> photographed."

The same section records the failure it replaces: seven testimonial portraits on the agency site are
stock photographs attached to the names of real people. The brand is explicitly "designed to survive
without commissioned photography." Diagrams are how that holds.

## Two phases

- **Phase A, author an archetype.** A new *kind* of diagram is invented and recorded in the ledger. Rare.
- **Phase B, illustrate an article.** The common path, below.

## Context to load

`references/art-direction.md` and `references/signature-ledger.md` always. Then
`references/diagram-archetypes.md` when choosing shapes, and `references/render-notes.md` when
authoring or debugging a render. **Max 3 per invocation.**

---

## Workflow (Phase B)

### Step 1. Read the article, not the brief

Read the actual markdown. Pull out:

- **The single claim a reader would argue with.** This becomes the cover. Not the topic, the claim.
- **The H2 sections carrying a mechanism**, ranked. Two or three become supporting figures.
- **One real measured number** from the article, for the cover footer.

If the article is thin enough that no claim stands out, say so. The problem is the article.

### Step 2. Check the ledger before choosing a cover shape

Read `signature-ledger.md`. The cover archetype must be a different **kind of object** from every
row already shipped. A restyle of an existing world does not count.

If every fitting archetype is taken, say so and propose one from the "still open" list rather than
repeating a world quietly.

### Step 3. Present the set and gate on it

Show, as a short list: the cover archetype and its accent subject, then each supporting figure with
the H2 it maps to. Then:

> Here is the image set. Tell me what to change, or say "render" when you are happy.

**Wait for approval.** Authoring SVG is cheap to change before it is drawn and tedious after.

### Step 4. Author the SVGs

To `content/blog/images/<slug>/{cover,fig-1,fig-2}.svg`. Follow the contract in
`references/render-notes.md`: viewBox, a real `aria-label`, full-bleed ground rect, palette-only
colours, at least one accent element.

Cover `0 0 1200 630`. Supporting `0 0 1200 800`.

### Step 5. Render and look at them

```bash
python scripts/render.py content/blog/images/<slug>/cover.svg --scale 2
```

**Then open the PNG and actually look at it.** The audit checks colour and size; it cannot see
overlapping text, a label running off the panel, or a drawing that is simply unclear. This step is
not optional and it is the one most likely to be skipped.

### Step 6. Record and hand off

Append a row to `signature-ledger.md`. Write the image paths and alt text into the article's Sheet
row so `website-creator` can render them.

## Scripts

```bash
python scripts/render.py FILE.svg [--out PNG] [--scale 2]
python scripts/render.py --selftest
```

`render.py` refuses to render an SVG that uses an off-palette colour, that uses the retired
`#475569`, or that contains no accent element. That refusal is the point: it is cheaper than
noticing in review.

`--selftest` runs 6 checks including whether glyph ink is genuinely present, which distinguishes
"the font loaded" from "the render silently produced a blank panel."

## Rules

- **One accent subject per image.** Several marks may belong to it. Two unrelated accented things is the failure.
- **The footer number must be real** and from this article. It is what stops the image being reusable filler.
- **Never edit a PNG.** The SVG is the source, the PNG is a build artefact.
- **Never mention the agency or the university** in image text, same voice contract as the articles.
- **No gradients, glow, 3D, stock, glowing brains or robot hands.** See `art-direction.md`.
- **Alt text is written, not generated.** It goes in the `aria-label` and must describe what the diagram argues, not that it is a diagram.

## Edge cases

| Situation | Action |
|---|---|
| Article has no arguable claim | Say so. Illustrating a vague article produces decoration. Fix the article first |
| Every fitting archetype is used | Propose from the ledger's "still open" list. Never repeat a world silently |
| Asked for a photograph or a person | Refuse and explain: `15` §6 records the live stock-photo credibility failure. Offer a logo or no image |
| Asked for more than 4 images | Push back. Beyond four the reader is scrolling past them. More figures usually means the article should be two articles |
| A label will not fit | Shorten the label, not the font size. Nothing below 14px in a 1200-wide image |
| Render hangs | Fonts are inlined so it is not a network stall. Check the SVG parses standalone in a browser first |
| Asked for a LinkedIn infographic | Route to `linkedin-infographics`. Different format, different mechanism |
| Asked for a carousel or a short | Route to `carousel` or `shorts-creator` |

## Trigger accuracy, measured

**13 of 14 (93%)**, 3 runs per query, `--num-workers 2`, 2026-08-22. Report in
`evals/trigger-results.json`, query set in `evals/trigger-evals.json`.

All 7 negatives pass at 0.00, including the four nearest neighbours: a LinkedIn infographic, an
Instagram carousel, a 9:16 short, and a rendered motion reel. Nothing bleeds into the siblings.

**The one residual failure, recorded rather than papered over:** *"Make some explainer diagrams to
go with the n8n post"* triggers at 1 of 3. It is a routing collision with the general-purpose
`diagram` skill on the bare word "diagram" without "blog" or "article" nearby. Rewriting this
description to claim the article-diagram case explicitly moved the pair of diagram-phrased queries
from 0/3 and 0/3 to 1/3 and 2/3, and took the set from 11/14 to 13/14. Pushing further would mean
stuffing the description hard enough to start winning queries that belong to the other skill, which
is a worse failure than this one. If it matters in practice, say "blog" or "article" in the ask.

## Boundaries

| Hand off to | For |
|---|---|
| `linkedin-infographics` | A single dense LinkedIn infographic from a Gemini prompt |
| `carousel` / `shorts-creator` | Instagram carousels and 9:16 short frames |
| `blog-writer` | Writing the article these images illustrate |
| `brand-visual` | Changing the palette or type system itself. This skill consumes `15`, it does not amend it |
| `website-creator` | Rendering the images into the live site |
